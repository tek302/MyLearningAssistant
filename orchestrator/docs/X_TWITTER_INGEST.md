# X (Twitter) URL Ingest — 왜 실패하는지 & 대안

## 1. 왜 X URL은 에러가 나는가?

일반 블로그(Google Blog 등)와 X(Twitter)의 차이:

| 구분 | 일반 블로그/기사 | X (Twitter) |
|------|------------------|--------------|
| **페이지 구성** | 서버에서 HTML을 완성해서 내려줌. 한 번의 GET으로 본문 텍스트가 HTML에 포함됨. | **JavaScript로 콘텐츠 로딩.** 처음 받는 HTML에는 거의 본문이 없고, 스크립트가 실행된 뒤에야 글이 채워짐. |
| **우리 백엔드** | `requests.get(url)` → 받은 HTML을 BeautifulSoup으로 파싱 → `<body>` 안의 텍스트 추출. | 같은 방식으로 받으면 **빈 페이지에 가까운 HTML**만 받음 → 추출된 텍스트가 거의 없음 → "No text content" 또는 최소 글자 수 미달 에러. |
| **봇 차단** | 대부분 단순 User-Agent만으로도 허용. | X는 자동화/봇 요청을 감지해 **다른 페이지를 주거나 로그인 유도**할 수 있음. |

정리하면, **X는 “한 번의 GET + HTML 파싱”으로는 본문을 가져올 수 없는 구조**라서 현재 URL ingest 방식으로는 실패하는 것이 맞습니다.

---

## 2. X 글을 ingest 하고 싶을 때 선택지

### A. X oEmbed 사용 (구현 가능, 인증 불필요)

X는 **oEmbed API**를 제공하고, **인증 없이** 트윗 URL만으로 내용을 받을 수 있습니다.

- **엔드포인트:** `https://publish.twitter.com/oembed?url=<트윗 URL>`
- **응답:** JSON 안에 `html` 필드로 트윗 본문이 들어 있는 HTML이 옴. 이 HTML에서 태그를 제거하면 순수 텍스트로 쓸 수 있음.

**백엔드에서 할 수 있는 것:**  
URL이 `twitter.com` / `x.com` 이면, 기존 HTML fetch 대신 oEmbed를 호출하고, 응답의 `html`에서 텍스트만 추출해서 지금과 동일한 “URL ingest 파이프라인”(chunk → embed → S1 등)에 넣으면 됩니다.

- **장점:** 트위터 개발자 계정/API 키 없이도 동작.  
- **제한:** oEmbed는 보통 **한 트윗 한 개** 단위. 스레드(여러 트윗)는 각각 URL로 넣어야 할 수 있음. rate limit 정책은 X 문서 확인 필요.

이 방식이 “X URL도 ingest 하고 싶다”는 요구에 가장 가깝고, **추가 권한이나 앱 설정은 필요 없습니다** (서버에서만 처리).

---

### B. 트위터 공식 API (가장 정확, 설정 필요)

- [Twitter API v2](https://developer.x.com/en/docs/twitter-api) 에서 앱을 만들고 API 키/토큰을 발급받음.
- 트윗 URL에서 트윗 ID를 추출한 뒤, API로 해당 트윗의 `text` 필드를 가져와서 ingest 파이프라인에 넣음.
- **장점:** 본문만 깔끔하게 받을 수 있고, 스레드 등도 API로 처리 가능.  
- **단점:** 개발자 계정·앱 생성·키 관리가 필요하고, 무료 한도/과금 정책을 봐야 함.

---

### C. 브라우저 렌더링 서비스 (Firecrawl, Browserbase 등)

- JavaScript까지 실행해서 “렌더링된 HTML”을 가져오는 서비스를 쓰면, X도 일반 웹페이지처럼 본문을 많이 추출할 수 있음.
- **장점:** X뿐 아니라 다른 JS 기반 사이트에도 적용 가능.  
- **단점:** 외부 서비스 비용·가입 필요, 응답 시간·안정성 이슈 가능.

---

### D. 사용자 수동 입력 (지금도 가능)

- 앱/백엔드에 **텍스트 직접 입력** ingest가 있다면, X 글을 **복사해서 붙여넣기**하면 됨.
- 현재 백엔드에 `type=text` ingest가 있으므로, Android에서 “텍스트로 추가” UI만 있으면 **지금 구조만으로** X 내용을 넣을 수 있음. (URL ingest 수정 없음.)

---

## 3. 권한 / 앱 설정

- **A (oEmbed):** 서버에서 `https://publish.twitter.com/oembed` 로 HTTPS 요청만 하면 되므로, **앱(Android) 쪽 추가 권한이나 설정은 필요 없음.**  
  (이미 네트워크 쓰는 앱이므로 권한도 동일.)
- **B (Twitter API):** API 키를 **백엔드만** 환경 변수 등으로 보관하면 되고, 앱은 기존처럼 “URL 하나 보내는 것”만 하면 됩니다. 앱에 추가 권한 필요 없음.
- **C:** 사용하는 서비스가 API 키만 요구하면 앱 권한은 그대로.
- **D:** 텍스트 입력만 쓰므로 권한 이슈 없음.

---

## 4. 제안

- **가장 빠르게 X URL을 지원하려면:** 백엔드에서 **A (oEmbed)** 를 추가하는 것을 권장합니다.  
  - URL이 `x.com`/`twitter.com`이면 `fetch_url_text` (또는 해당 호출부)에서만 oEmbed를 호출하고, 나온 `html`에서 텍스트 추출 후 기존 플로우에 넘기면 됩니다.
- 그다음으로, **사용자에게 “긴 스레드는 텍스트로 붙여넣기”** 옵션을 안내해 두면 (D), oEmbed 한계를 보완할 수 있습니다.

원하시면 `web_fetch` (또는 URL ingest 진입점)에 **X URL일 때만 oEmbed 경로**를 넣는 코드 변경 예시까지 이어서 제안하겠습니다.
