# Learning Assistant — 시장 대비 검토 (PM/VC 관점)

**기준:** 태그 `v1.0-week9` (MVP Week 10 완료).  
**목적:** 현재 서비스 중인 유사 툴/서비스와 기능·완성도 측면에서 비교하고, 냉정한 포지셔닝과 갭을 정리한다.

---

## 1. 우리 제품 한 줄 요약

**“모바일(Android)에서 URL/PDF를 넣으면, RAG로 질의응답하고, 토픽 단위 주간 요약(S2)과 주간 추천(arXiv Top-3)까지 한 번에 도는 개인용 AI 어시스턴트”**

- Ingest (URL/PDF) → S1 → RAG (pgvector + eval/refine) → S2 배치 → 주간 추천 배치
- Android 앱: 질의응답, 공유 ingest, 상태 확인, 피드(S1), Weekly Summary(S2), Recommendations(Process/Remove·필터)

## 3. 강점 (Differentiation)

1. **파이프라인 한 번에**
   - Ingest → S1 → RAG → **S2(토픽 단위 장기 기억)** → **주간 추천(토픽당 arXiv Top-3)** 까지 한 제품에서 처리하는 서비스는 거의 없음.
   - Matter/Readwise: RAG·요약은 있으나 S2 스타일 통합 요약·토픽별 추천 없음.
   - Elicit: 논문 중심, “내가 넣은 URL/PDF + 토픽 모델 + 주간 추천” 조합이 아님.
   - Mem: 노트·캡처 중심, URL/PDF ingest 파이프라인과 S2/추천 파이프라인 없음.

2. **RAG 품질**
   - Rule-based eval + LLM judge + refine loop으로 “할 수 없으면 못 답함” 처리·품질 가드가 설계에 포함됨. 일반적인 “챗에 파일 첨부” 수준을 넘어섬.

3. **모바일 퍼스트**
   - “어디서나 Android로 넣고, 물어보고, 주간 요약·추천까지 본다”는 시나리오가 처음부터 타깃. (iOS/웹은 미지원.)

## 5. PM/VC 관점 요약

- **포지셔닝**
  - “개인용 읽기/저장 + RAG + **토픽 단위 장기 요약(S2)** + **주간 추천**”을 한 번에 하는 건 차별화됨. 특히 S2 + 주간 추천 조합은 유사 제품에서 거의 안 보임.
  - 다만 **타깃이 “연구/학습에 쓰는 개인”**인지, “일반 읽기 관리”인지에 따라 경쟁자가 달라짐. 연구 쪽이면 Elicit과 비교·통합 이야기, 일반이면 Matter/Readwise와 비교가 맞음.

- **완성도**
  - **기능 완성도:** 시나리오 기준으로는 “한다”는 걸 증명한 상태. **제품 완성도:** 프로덕션 안정성·관측성·멀티유저·폴리시된 UX는 Post-MVP. 따라서 “실서비스 수준”과 비교하면 **아직 프로토타입/데모에 가깝다**고 보는 게 맞음.

- **투자/사업 관점**
  - 강한 조합(특히 S2 + 추천)과 RAG 품질 설계는 스토리로 쓸 만함.
  - 갭: 플랫폼(Android만), 프로덕션화, 피드백·개인화, Ingest 복원력. 이 갭을 어떻게·어디서부터 메울지가 “다음 6개월”의 핵심 질문.
  - 경쟁사 대부분은 이미 유료·팀 플랜·브랜드 있음. “우리만의 조합(S2 + 주간 추천)”을 명확히 하고, 타깃 유저(예: 연구자·직장인 학습)를 좁혀서 그 조합을 필수로 만드는 게 중요.

## 6. 참고: 경쟁사 핵심만

- **Matter:** 읽기 수집·뉴스레터·팟캐스트, Co-Reader(Q&A는 Perplexity). “내 라이브러리 RAG”·토픽 요약·추천 없음.
- **Readwise Reader:** 하이라이트 + 문서별/전체 채팅(RAG 유사). S2·주간 추천 없음. 읽기 리뷰·습관에 강점.
- **Elicit:** 논문 1억+ 건, 시맨틱 검색·요약·시스템ати크 리뷰·PDF 업로드. “임의 URL/PDF + 개인 토픽 + 주간 추천”이 아닌 연구 워크플로우.
- **Mem:** 캡처·노트·Mem Chat(노트 기반 Q&A)·Heads Up. URL/PDF ingest 파이프라인·S2·추천 파이프라인 없음.
